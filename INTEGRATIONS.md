# Entegrasyonlar — kurulum adımları

Site statiktir (GitHub Pages). Form ve Google yorumları için ayrı bir **Cloudflare Worker** (`worker/`) kullanılır.
Hiçbir entegrasyon zorunlu değildir: kimlikler boşken site güvenli fallback'lerle çalışır.

| Özellik | Kimlik yokken | Kimlik varken |
|---|---|---|
| Randevu formu | Doğrulanmış alanlar hazır **WhatsApp mesajına** dönüşür (sunucuya veri gitmez, sahte "gönderildi" yok) | Worker'a JSON POST → e-posta (+ isteğe bağlı Telegram) → yalnızca `delivered:true` ise "alındı" |
| Google yorumları | Takeout'tan statik seçki (karusel) ya da `link` modunda yalnız Google bağlantı kartı | Karusel: Worker, Places API (New) ile güncel puan + listede olmayan en fazla 5 yeni yorum (tekrar/çıkarılmış yorum elenir). `link`: çağrı yok |
| GA4 / Google Ads / Meta / OpenAI | Hiç yüklenmez | Yalnızca çerez izniyle yüklenir |
| Turnstile | Yok | Formda görünmez bot koruması |
| Harita | Doğrudan yüklenen Google Haritalar gömmesi (izinden bağımsız; bkz. §4) | aynı |

## 1. Worker (form + yorumlar)

Ayrıntı: `worker/README.md`. Özet:

```bash
cd worker && npm install
npx wrangler login
# Sırlar
npx wrangler secret put RESEND_API_KEY        # veya BREVO_API_KEY
npx wrangler secret put GOOGLE_PLACES_API_KEY
npx wrangler secret put GOOGLE_PLACE_ID
npx wrangler secret put TURNSTILE_SECRET_KEY  # isteğe bağlı
npx wrangler secret put TELEGRAM_BOT_TOKEN    # isteğe bağlı
npx wrangler secret put TELEGRAM_CHAT_ID      # isteğe bağlı
npx wrangler deploy
```

`wrangler.jsonc` içindeki `vars`: `ALLOWED_ORIGINS` (https://keciorenisitme.com), `MAIL_PROVIDER` (`resend` | `brevo` | `mock`), `MAIL_FROM`, `MAIL_TO` (ayazisitmecihazlari@gmail.com), `REVIEWS_CACHE_TTL` (varsayılan 0).

Sitede: `.env` → `PUBLIC_API_BASE=https://<worker-adresi>` (ör. `https://api.keciorenisitme.com` özel alan adı veya `https://ayaz-isitme-api.<hesap>.workers.dev`). GitHub Actions için repo **Variables** altına aynı adla ekleyin.

### E-posta sağlayıcısı
- **Resend** (önerilen basitlik): ücretsiz kotası vardır; gönderen alan adı doğrulaması ister (`keciorenisitme.com` DNS kayıtları). Gmail'e teslimat için `MAIL_TO` yeterlidir.
- **Brevo**: alternatif; API anahtarı ile aynı şekilde.
- **KVKK notu:** Bu sağlayıcıların sunucuları yurt dışındadır; randevu verisinin (ad, telefon) yurt dışına düzenli aktarımı KVKK m.9 kapsamındadır (standart sözleşme + Kurum'a bildirim ya da veriyi Türkiye'de tutan mimari). Karar avukatla verilmeli; karar verilene kadar **API'siz WhatsApp modu** en düşük riskli seçenektir (veri doğrudan ziyaretçinin WhatsApp'ından işletmeye gider, aracı sunucu yoktur).

### Google yorumları (Places API New)
1. Google Cloud'da proje → **Places API (New)** etkinleştir → API anahtarı oluştur → **API kısıtlaması: yalnızca Places API (New)**. Anahtar yalnızca Worker sırrında durur, siteye asla yazılmaz.
2. Place ID: **`ChIJFz--mydN0xQRGFX1eR6q5s8`** (işletmenin Takeout dışa aktarımından doğrulandı, `business.google.placeId`). Worker'da `wrangler secret put GOOGLE_PLACE_ID` ile bu değeri girin.
3. Maliyet: `reviews` alanı **Place Details Enterprise + Atmosphere** SKU'suna girer — aylık **1.000 çağrı ücretsiz**, sonrası 1.000 çağrı başına ≈25 USD (2026-09 fiyat listesi). Yorum bölümü yalnızca ekrana yaklaşınca çağrı yapar.
4. Politika: Google Maps Platform şartları yorum içeriğinin önbelleklenmesine/saklanmasına açıkça izin vermez (yalnızca Place ID saklanabilir). Worker varsayılan olarak canlı çeker; `REVIEWS_CACHE_TTL` ile önbellek açmak işletmenin uyumluluk kararıdır. Sitede zorunlu atıflar uygulanır: yazar adı/avatarı/profil bağlantısı, "Google Maps" metni, yoruma ve işletmeye Google bağlantısı, göreli tarih.
5. "Yorum yaz" bağlantısı: Google İşletme Profili > Yorumları oku > **Daha fazla yorum alın** > bağlantıyı kopyala → `business.google.writeReviewUrl`.

## 2. Ölçüm (izinle)

Tüm kimlikler `.env` / GitHub Variables ile verilir; boşsa ilgili script hiç yüklenmez.

| Değişken | Ne | Not |
|---|---|---|
| `PUBLIC_GA4_ID` | GA4 ölçüm kimliği (`G-…`) | Mevcut sitede `G-VRC710M0YF` kullanılıyor; aynı mülk kullanılabilir. Consent Mode v2 temel modu: izin yoksa gtag.js yüklenmez. Google sinyalleri ve reklam kişiselleştirme kapalı. |
| `PUBLIC_GADS_ID` | Google Ads (`AW-…`) | Pazarlama izniyle yüklenir. |
| `PUBLIC_GADS_APPOINTMENT_LABEL` | Dönüşüm etiketi | `appointment_submit_success` olayında `AW-…/etiket` dönüşümü gönderilir. Telefon/WhatsApp tıklamaları GA4 olayı olarak gider; Ads'te "tıklama = arama" sayılmaz. |
| `PUBLIC_META_PIXEL_ID` | Meta Pixel | Pazarlama izniyle; yalnızca standart olaylar (`PageView`, `Contact`, `Lead`), LDU açık, gelişmiş eşleştirme yok. Meta bu siteyi "Sağlık ve zindelik" kategorisine alıp **Temel Kurulum** kısıtı uygulayabilir; URL parametrelerine sağlık terimi konmaz. |
| `PUBLIC_OPENAI_PIXEL_ID` | ChatGPT Ads pikseli | Resmî `oaiq` yükleyici hazır; ancak OpenAI reklam politikası ABD dışı sağlık hizmetleri reklamlarını "genellikle yasak" sayıyor (10 Eyl 2026 sürümü). Hesap/kategori onayı gelmeden **boş bırakın**. |
| `PUBLIC_TURNSTILE_SITE_KEY` | Cloudflare Turnstile | Worker'a `TURNSTILE_SECRET_KEY` de eklenmeli. |

İç olay sözlüğü (`track()`): `phone_click`, `whatsapp_click`, `directions_click`, `appointment_start`, `appointment_submit_success`, `appointment_submit_whatsapp`, `product_explore`, `reviews_click`, `review_write_click`. Hiçbir olayda ad, telefon veya form içeriği gönderilmez.

Google Ads politikası: sağlık "hassas ilgi kategorisi" — **yeniden pazarlama / müşteri eşleştirme / benzer kitle kullanmayın**; anahtar kelime + konum + hazır kitlelerle çalışın. Türk mevzuatı: işitme cihazı **ürün** reklamı tüketiciye yapılamaz (Tıbbi Cihaz Satış, Reklam ve Tanıtım Yönetmeliği m.15); reklamlar **merkez ve hizmetleri** için kurgulanmalı.

## 3. Organik arama ve yapay zekâ botları

- `public/robots.txt`: tüm botlara açık; `OAI-SearchBot` ve `ChatGPT-User` açıkça izinli (ChatGPT aramasında görünürlük). `GPTBot` (eğitim) ayrıca engellenmedi; istenirse `Disallow` eklenir — arama görünürlüğünü etkilemez.
- Sitemap: `https://keciorenisitme.com/sitemap-index.xml` (build'de üretilir; robots.txt içinde).
- Search Console: yeni yapı yayına alındıktan sonra sitemap gönderin; `/en/` için hreflang otomatik.

Testte çerez görülmemesi garanti değildir: Google bölgeye, Google hesabına giriş durumuna ve tarayıcının üçüncü taraf çerez ayarına göre çerez koyabilir (ör. `NID`, `AEC`, `SOCS`, `__Secure-ENID`) ya da mevcut google.com çerezlerini okuyabilir. ## 5. Yorumlar (statik veri + içe aktarma)

`src/content/reviews-data.json` kaydırıcıyı ve özet kartını besler.
- **Tüm yorumları almak için (önerilen):** işletme hesabıyla https://takeout.google.com → yalnızca "Google Business Profile" → dışa aktar → zip'i aç → `node scripts/import-google-reviews.mjs "<klasör>" --as-of=<dışa aktarım günü YYYY-MM-DD>`. Betik ağ isteği yapmaz; Google çevirili yorumlarda özgün metni alır, tekrarları eler, metinsiz (yalnız puan) yorumları özete sayar ama kaydırıcıda göstermez. `--as-of` verilmezse bugünün tarihi yazılır.
- Elle ekleme: aynı JSON biçimine satır ekleyin (`author`, `rating`, `text`, `approxDate`).
- Ad gösterimi: `business.reviewsShowFullNames` (varsayılan kapalı → "Ad S."). **Tek kelimelik görünen adlar** (ör. ad ve soyadın bitişik yazıldığı bir kullanıcı adı) bu kuralla kısaltılamaz ve olduğu gibi görünür; bu, yazarın Google'daki **kendi herkese açık görünen adıdır**. İşletme sahibi isterse `src/content/reviews-curation.json` > `displayNames` (`{ "<yorum kimliği>": "<gösterilecek ad>" }`) ile yorum başına başka bir biçim verir; içe aktarıcı uygular (değer sitede yine "Ad S." kuralından geçer; veride olmayan/boş kayıtlar uyarıyla yok sayılır). Harita **boş** bırakıldı: hiçbir ad biçimi uydurulmadı. Yalnızca statik kartın görünen adı değişir; parmak izleri Google'daki adla hesaplanır. Canlı modda aynı yazarın **yeni** bir yorumu Google'daki adıyla (kısaltma kuralıyla) görünür.
- **Gösterim modu (hukuki karar):** `business.reviewsDisplay` ya da derleme değişkeni `PUBLIC_REVIEWS_DISPLAY` → `carousel` (yorumlar + puan) | `link` (yalnızca Google profil bağlantısı; metin/puan/adet yok, Worker'a yorum çağrısı da yapılmaz). GitHub Actions `vars.PUBLIC_REVIEWS_DISPLAY` değerini okur. Gerekçe: CONTENT-VERIFICATION.md §9. `link` modu otomatik testle kanıtlanır: `tests/e2e/reviews-link-mode.spec.ts` gerçek bir `PUBLIC_REVIEWS_DISPLAY=link` derlemesi (geçici klasör) alır; HTML'de yorum kancası/metni/puanı olmadığını ve `PUBLIC_API_BASE` tanımlıyken bile `/api/reviews`'e istek gitmediğini doğrular.
- **Seçki:** `src/content/reviews-curation.json` → `pin` (TR sabit sıra), `enPin` (EN sabit sıra), `exclude` (kategorili, gerekçeli), `enExclude` (kategorili), `displayNames` (isteğe bağlı görünen ad; yukarıya bakın). Kategoriler:
  - `exclude[].category = "legal-risk"` → **gösterilmez**: açık sağlık/tedavi sonucu iddiası, rakip kıyası ya da kötüleme, marka/model adı, fiyat iddiası veya doğrulanamaz üstünlük ("tek adresi", "en iyi"), olası çıkar çatışması (Salih P.: profil yöneticisiyle aynı ad — **teyit edilmedi, işletme sahibi teyit etmeli**).
  - `exclude[].category = "editorial"` → **gösterilir**, sırada geride (kısa/zayıf metin, argo, "kulaklık", "yeni açıldı", marka/model içermeyen genel "cihazdan memnunuz").
  - `enExclude[].category = "translation-error"` → yalnız İngilizce sayfada gösterilmez (Google çevirisi özgünü çarpıtıyor: "headphones", "my brother Emre", "hear about the cold"); `"editorial"` → İngilizcede de gösterilir, geride. Kategorisiz kayıt güvenli tarafta kalır (gösterilmez).
  - Durum (26 Eyl 2026): 58 metinli yorumdan **TR 53**, **EN 47** gösteriliyor; 5 `legal-risk` gizli, 17 `editorial` geri alındı; EN'de ayrıca 6 `translation-error`.
  - Değiştirince içe aktarıcıyı yeniden çalıştırın; Takeout zip'i yeniden gerekmez, açılmış klasör yeterli.
- **Canlı API modu (PUBLIC_API_BASE + karusel):** Worker'dan gelen (en fazla 5) yorum yalnızca statik listede yoksa ve seçkide çıkarılmış bir yorum değilse başa eklenir. Eşleştirme `scripts/lib/review-fingerprint.mjs` ile yapılır (içe aktarıcı ve tarayıcı aynı kodu kullanır). **Kısa ad ("Ad S.") yalnızca gösterim içindir; kısa ad + ay da, 40 karakterlik ortak açılış da tek başına hiçbir canlı yorumu elemez** (ne statik kartın tekrarı ne de çıkarılmış yorum olarak). Parmak izleri (FNV-1a 32 bit özet, önek harfiyle):
  - `t…` metin: sadeleştirilmiş (küçük harf, Türkçe harfler sadeleşmiş, boşluk/emoji/noktalama atılmış) metnin ilk 40 karakteri (daha kısa metinde tamamı) — TR özgün **ve** EN çeviri ayrı ayrı. "Uzun metin" = sadeleştirilmiş hâli ≥ 40 karakter.
  - `i…` Google yorum kimliği: Takeout'ta `accounts/…/locations/…/reviews/{id}`, Places API (New)'de `places/{placeId}/reviews/{id}` son parçası. Worker bu son parçayı `id` alanında döndürür (geriye dönük uyumlu ek alan; `publishTime` zaten vardı). **İki kimliğin aynı olduğu kanıtlanmadı** (Google belgelerinde bu garanti yok; bu işletme için canlı API yanıtıyla karşılaştırılmadı). Bu yüzden kimlik eşleşmesi yalnızca **olumlu** işarettir (eşleşirse aynı yorumdur); eşleşmemesi "farklı yorum" sayılmaz ve diğer kurallara geçilir.
  - `m…` kısa ad + yayın ayı (`YYYY-MM`, UTC): Takeout'ta `createTime` **ve** `updateTime` ayları için ayrı ayrı; canlı yorumda `publishTime` ayı. `publishTime` yoksa bu anahtar üretilmez. Anonim adlar ("Google kullanıcısı") anahtar üretmez.
  - **Eşleştirme kayıt başınadır ve iki listede aynıdır.** Kayıtlar: (a) her statik kart ve kabul edilen her canlı yorum — kendi `t`/`i`/`m` anahtarları ve metinlerinin kelime kümeleri (kelimeler sadeleştirilir, ≥ 2 harf, bellekte özetlenir; kartın metinleri: sayfada görünen metin, EN sayfasında ayrıca kartın özgün TR metni — `data-alt-text` özniteliği, görünmez; Google'ın çevirmeden özgünü döndürdüğü durum için, metin zaten TR sayfasında herkese açık); (b) seçkide çıkarılan **her yorum için tek koruma kaydı** — kendi `t` (TR özgün ve EN çeviri), `i`, `m` (oluşturma/güncelleme ayı) anahtarları ve TR/EN metinlerinin kelime kümesi **özetleri** (metin yok; biçim aşağıda). Koşullar **farklı kayıtlardan birleştirilmez** (ör. `t` kayıt A'da, `m` kayıt B'de → eşleşme değil).
  - **Eşleşme ⇔ aynı kayıt c için** şunlardan biri: (1) aynı `t` **ve** — uzun metinde — canlı metin ile c'nin metinlerinden biri arasında kelime kümesi Jaccard benzerliği ≥ **0,6**; kısa metinde aynı `m` **de c'de**; **ya da** (2) aynı `i`; **ya da** (3) aynı `m` **ve** Jaccard ≥ **0,35**. Karar sırası: önce koruma kayıtları (eşleşirse **engellenir**), sonra kartlar (eşleşirse **tekrar**); her listede (1), (2), (3).
  - Eşik gerekçeleri (26 Eyl 2026 ölçümü, bu işletmenin 53 TR + 47 EN statik metni): **0,6** (uzun metin + ortak 40 karakterlik açılış): gürültü (emoji/boşluk/büyük harf/noktalama) varyantı 1,0; sonuna cümle eklenmiş aynı metin 0,64–0,96 (91/91 ≥ 0,6); son cümlesi atılmış 46/59 ≥ 0,6. Aynı açılışla başlayıp başka bir statik yorumun gövdesiyle süren 8.190 sentetik metnin %12,3'ü ≥ 0,5, %4,6'sı ≥ 0,6 (hepsi sadeleştirilmiş uzunluğu 41–136 karakter olan, açılışı metnin büyük kısmı olan statik metinlerde) → eşik gösterme yönünde seçildi. **0,35** (kısa ad + ay): farklı yorum çiftlerinin yalnızca %1,26'sı ≥ 0,35 (en yüksek 0,53: çok kısa, kalıp metinler); aynı ay içinde **sonuna cümle eklenerek** düzenlenmiş metinler 0,57–0,64 (ilk cümlesi silinen düzenlemeler daha düşük kalabilir, bkz. risk 9); aynı yorumun elle yazılmış yeniden çevirileri **0,27–0,53** (8 örnekten 5'i 0,35'in altında; önceki bağımsız ölçüm 0,33–0,48). Örnekler `tests/reviews-import.test.ts` içinde.
  - **Çıkarılmış yorum (engellenir) ⇔** yukarıdaki kurallardan biri **aynı koruma kaydıyla** tutar (tur 6'ya kadar `t`, `i` ya da `m` tek başına yetiyordu; GPT incelemesi: aynı kısa ad + ay ya da ortak 40 karakterlik açılış başka bir kişiyi gizleyebiliyordu → kaldırıldı). Koruma listesi = `legal-risk` ile çıkarılanlar; EN sayfasında ayrıca `translation-error` olanlar (26 Eyl 2026: TR 5, EN 11 kayıt). Derlemede sayfaya `[data-reviews-guard]` JSON'u olarak yazılır: `[{ "fp": ["t…", "t…", "i…", "m…"], "w": ["<TR kelime özetleri>", "<EN kelime özetleri>"] }, …]` — `w` her metnin kelime kümesidir: sadeleştirilmiş kelimenin FNV-1a 32 bit özeti (8 hex), **sıralı** (metindeki kelime sırası yazılmaz), boşlukla ayrılmış. Boyut: TR ≈ 3,4 KB, EN ≈ 6,3 KB. Koruma listesi yoksa, JSON değilse ya da bir kaydı bozuksa (dizi değil, `fp`/`w` yok, hiç geçerli anahtar yok, 8 hex olmayan kelime özeti; eski düz anahtar listesi de bozuk sayılır) `parseGuard` hata verir ve **API hiç çağrılmaz**.
  - **Koruma kaydının gizliliği:** metnin, adın ya da tarihin kendisi yazılmaz, ama özetler **tuzsuzdur**: (a) bir ad ve ay tahmin edilerek "bu kişinin o ayki yorumu çıkarılmış" doğrulanabilir; (b) bir sözlükle (Türkçe/İngilizce kelime listesi) her kelime özeti denenerek çıkarılan metinlerin kelimelerinin çoğu **sırasız** geri bulunabilir. Bu metinler Google'da zaten herkese açıktır; yine de sayfa kaynağında ve herkese açık depoda (`reviews-data.json`) çıkarılan yorumların kelime kümesi özet olarak bulunur. **Derleme başına tuz koruma sağlamaz:** tarayıcı canlı metni aynı tuzla özetlemek zorunda olduğundan tuz sayfada yayımlanır; sözlük saldırısı aynı tuzla yapılır. Kelime özetlerini sayfaya hiç koymamanın tek yolu eşleştirmeyi sunucuda (Worker, gizli anahtarla) yapmaktır — yapılmadı. Ölçüm (27 Eyl 2026, 11 koruma kaydının 22 TR/EN metni): birebir, emoji/büyük harf/boşluk varyantı ve sonuna cümle eklenmiş hâli 22/22 `text` kuralıyla engellenir (ad/tarih gerekmez); son cümlesi atılmış hâli 21/22 (kalan: 81 karakterlik bir EN çeviri; aynı kısa ad·ay varsa (3) yakalayabilir). Hiçbir statik kart (TR 53, EN 47) bir koruma kaydıyla eşleşmez.
  - Her statik kartta `data-fp` (yalnızca `t`/`i`/`m` özetleri) vardır; canlı yorumlar kendi aralarında da aynı kurallarla tekilleştirilir. Hiçbir anahtar üretmeyen canlı yorum (≤ 3 harflik metin, kimlik ve tarih yok) eklenmez.
  - **Kalan riskler — yanlışlıkla gizleme:** (1) Aynı kısa adlı **farklı** bir kişi, çıkarılmış bir yorumla **aynı ayda** ve o yorumun TR ya da EN metniyle Jaccard ≥ 0,35 bir metin yazmışsa gizlenir. Ölçüm: çıkarılmış 22 metin × diğer statik metinler (2.188 çift, diller karışık) → %0,37'si ≥ 0,35 (en yüksek 0,47); aynı dilde bakıldığında EN ≈ %1,2, TR %0 (bağımsız doğrulama, 27 Eyl 2026); ayrıca kısa ad ve ay da tutmalıdır (26 Eyl 2026 verisinde `legal-risk` yorumların ayları 2024-03 ile 2025-07, EN `translation-error` olanlarınki 2024-02 ile 2026-03 arasında; sonraki aylarda yazılan yorumlar bu kurala hiç takılmaz). (2) Aynı kısa adlı farklı bir kişi, statik bir kartla aynı ayda ve o kartla Jaccard ≥ 0,35 bir metin yazmışsa tekrar sayılıp gösterilmez (kozmetik). (3) Farklı bir kişinin uzun yorumu statik bir kartla aynı 40 karakterlik açılışla başlıyor **ve** o kartla Jaccard ≥ 0,6 ise gizlenir (kozmetik; sentetik ölçümlerde yaklaşık %4–11, çoğunlukla devamı birkaç kelime olan kısa statik metinlerde). (4) Aynısı koruma kaydı için: çıkarılmış bir metinle aynı 40 karakterlik açılışla başlayan **ve** onunla Jaccard ≥ 0,6 olan farklı bir yorum gizlenir. Ölçüm (27 Eyl 2026): çıkarılmış metnin açılışı + başka bir statik yorumun gövdesi olan 1.946 sentetik metnin 13'ü (%0,67), hepsi sadeleştirilmiş uzunluğu 81–89 karakter olan en kısa çıkarılmış metinlerde. Koruma listesinde kısa (< 40 karakter) metin yok (TR `legal-risk`: 149–344, EN 159–288; EN `translation-error`: TR 81–266, EN 85–272 karakter); kısa bir metin eklenirse aynı kaydın `m`'si de gerekir. (5) Aynı ay ve aynı kısa adlı iki farklı kişinin canlı yorumları %35+ ortak kelime içeriyorsa ikincisi gizlenir (kozmetik). (6) 32 bit özet çakışması: sayfadaki birkaç yüz anahtara karşı yorum başına ~10⁻⁷ mertebesinde; iki metnin kelime özetleri arasında yanlış ortak kelime olasılığı (~50 × 50 / 2³²) ihmal edilebilir.
  - **Kalan riskler — tekrarın gösterilmesi (kozmetik):** (7) Kısa metinli bir tekrar, canlı yorumda `publishTime` yoksa ya da yazar anonimse (`m` yok) gösterilir. (8) EN yeniden çevirisi (Google'ın aynı yorumu farklı ifade ettiği çeviri) statik çeviriyle Jaccard < 0,35 ise gösterilir (ölçülen aralık 0,27–0,53; 8 örneğin 5'i altında); `publishTime` yoksa daha yüksek benzerlikte de (açılış aynı ve ≥ 0,6 değilse) gösterilir. (9) Aynı ay içinde **açılış cümlesi silinerek** düzenlenmiş yorum: `t` değişir; (3) ancak Jaccard ≥ 0,35 ise yakalar — çok cümleli 59 statik metinde ilk cümle atılınca 5/59'u 0,35'in altında (en düşük 0,14). (10) Düzenlenmiş statik yorum **başka ayda** ya da uzun metinde 0,6'nın altında kalacak kadar değişmişse (son cümle atılınca 13/59) bir kez tekrar görünebilir; `publishTime` yoksa yalnızca (1)-uzun metin ve (2) çalışır. (11) EN sayfasında Google çevirmeden özgün TR metni döndürürse TR `t` + `data-alt-text` ile yakalanır; TR sayfasında ise kartın EN çevirisi sayfada olmadığından uzun bir EN metin `t` kuralıyla eşleşmez (TR sayfası `lang=tr` ister; Google'ın TR yorumu EN döndürmesi beklenmez).
  - **Kalan riskler — çıkarılmış yorumun geri gelmesi (hukuki yön; canlı API açılmadan önce değerlendirilmeli):** (12) **EN sayfası, yeniden çeviri:** Places API'nin bugünkü İngilizce çevirisi Takeout'taki çeviriden farklıysa, çıkarılmış yorum yalnızca şu durumda engellenir: açılış aynı ve Jaccard ≥ 0,6, ya da aynı kısa ad + ay ve Jaccard ≥ 0,35, ya da kimlik eşleşmesi. Elle yazılmış yeniden çevirilerde benzerlik 0,27–0,53 (8 örneğin 5'i 0,35'in altında) → kimlik eşleşmezse geri görünebilir. Önlem seçenekleri: canlı API'yi açmadan önce Places `reviews[].name` kimliğinin Takeout kimliğiyle aynı olduğunu bu işletme için doğrulamak ((2) o zaman her çıkarılmış yorumu yakalar); ya da Worker'ın çeviride özgün TR metni de (`originalText`) döndürmesi ve bunun eşleştirmeye girmesi (yapılmadı: Worker değişmedi; `worker/test/validate.test.ts` `originalText`'in sızmamasını bilerek sınıyor). (13) Çıkarılmış bir yorum Takeout'tan **sonra** düzenlenirse: açılışı değişmişse ya da Jaccard < 0,6 kalacak kadar değişmişse ve (başka ayda ya da Jaccard < 0,35) ve kimlik eşleşmiyorsa geri görünebilir → düzenli yeniden içe aktarın (90 gün uyarısı). (14) `publishTime` gelmeyen ya da anonim yazarlı yorumlarda `m` yoktur: yalnızca (1)-uzun metin ve (2) çalışır; kısa bir çıkarılmış metin (şu an yok) bu durumda engellenmez. (15) **Görünen ad (Tur 10):** canlı API'den gelen tek kelimelik Google adları olduğu gibi gösterilir ("Ad S." kuralı iki kelime ister). Bitişik yazılmış ad-soyad kullanıcı adı (ör. statik veride `displayNames` ile düzeltilen kayıt) canlıda tam ad gibi görünebilir; otomatik kural gerçek tek adları ("Abdulkadir") bozacağı için eklenmedi. Canlı API'yi açmadan önce yeni gelen yorumların adları gözden geçirilmeli.
